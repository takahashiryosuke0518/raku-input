# らくらくにゅうりょくん！ MVP 設計

## 目的

Webフォームへ繰り返し入力する氏名情報を、利用者がChrome拡張機能へ一度登録し、明示的なボタン操作で現在のページへ自動入力できるようにする。MVPでは「姓」「名」「英字姓」「英字名」の4項目だけを扱う。

成功条件は、拡張機能をManifest V3として読み込めること、4項目を保存・復元できること、対応する入力欄だけへ値を設定できること、フォームを送信しないことである。

## スコープ

### 対象

- Chrome Extension Manifest V3
- ポップアップからの4項目の登録、保存、復元
- `chrome.storage.local` への保存
- 利用者が「このページに入力」を押したときだけ行う自動入力
- `label`、`placeholder`、`name`、`id`、`aria-label`、`autocomplete` に基づく入力欄判定
- 判定結果と処理結果の簡潔なステータス表示

### 対象外

- フォーム送信
- 住所、電話番号、メールアドレスなど4項目以外の情報
- 外部API、AI、解析サービス、ネットワーク通信
- アカウント同期、暗号化、エクスポート、複数プロフィール
- iframe内およびShadow DOM内の入力欄
- `chrome://`、Chromeウェブストアなど、Chromeがスクリプト注入を禁止するページ

## 技術方針

依存パッケージを追加せず、HTML、CSS、JavaScriptだけで構成する。自動入力は `activeTab` と `scripting` 権限によるプログラム注入とし、常時すべてのサイトへアクセスするホスト権限は要求しない。登録情報はソースコードへ記載せず、`chrome.storage.local` の `profile` キー配下だけに保存する。

## ファイルと責務

- `manifest.json`
  - Manifest V3のメタデータ、ポップアップ、`storage`、`activeTab`、`scripting` 権限を宣言する。
- `popup.html`
  - 4入力欄、「保存」、「このページに入力」、ステータス表示を持つ。インラインスクリプトは使わない。
- `popup.css`
  - 小さなポップアップで読みやすく操作できる最小限の見た目を定義する。
- `profile-storage.js`
  - プロフィールの既定形、保存、取得を担当する。Chrome APIを引数として受け取り、単体テスト可能にする。
- `autofill.js`
  - DOM要素から手掛かりを収集し、4項目のどれに対応するかを判定し、値を設定する。Chrome APIには依存しない。
- `content.js`
  - `chrome.storage.local` からプロフィールを取得し、`autofill.js` を現在のページで実行して結果を返す薄いアダプターとする。
- `popup.js`
  - ポップアップの初期復元、保存ボタン、現在タブへのスクリプト注入、利用者向けステータスを担当する。
- `tests/profile-storage.test.js`
  - 保存・復元と欠落値の正規化を検証する。
- `tests/autofill.test.js`
  - 判定規則、未対応欄の除外、値設定とイベント送出を検証する。
- `tests/fixtures/test-form.html`
  - Chromeへ読み込んだ拡張機能を手動確認するためのローカルフォームを提供する。
- `package.json`
  - Node.js組み込みテストランナーを呼び出す `test` スクリプトだけを定義し、依存関係は持たない。

## 保存データ

保存形式は次の固定形とする。値はすべて文字列であり、未入力値は空文字列に正規化する。

```json
{
  "profile": {
    "familyName": "",
    "givenName": "",
    "familyNameLatin": "",
    "givenNameLatin": ""
  }
}
```

保存操作は4項目を一括で置き換える。ポップアップを開いたときは保存済みの値を取得して各欄へ復元する。登録値をHTML、JavaScript、テストへ埋め込まない。

## 入力欄の判定

### 対象要素

対象は、無効化または読み取り専用ではない、`type` が未指定または `text` の `input` とする。`hidden`、`password`、`email`、`tel`、`search` など他用途の型、`textarea`、`select`、ボタン類は対象外とする。

各要素について、関連付けられた `label[for]`、親 `label` のテキスト、`placeholder`、`name`、`id`、`aria-label`、`autocomplete` を収集する。英字は小文字化し、区切り文字、空白、全角・半角の差を正規化してから判定する。

### 対応語

- `familyName`: 「姓」「苗字」「名字」および、それらを含む日本語の表記
- `givenName`: 「名」「名前（名）」「下の名前」および、それらを含む日本語の表記
- `familyNameLatin`: 「英字姓」「ローマ字姓」「姓（英字）」「姓（ローマ字）」、`last name`、`family name`、`surname`、`last_name`、`family-name`、`familyName`、`autocomplete="family-name"`
- `givenNameLatin`: 「英字名」「ローマ字名」「名（英字）」「名（ローマ字）」、`first name`、`given name`、`first_name`、`given-name`、`givenName`、`autocomplete="given-name"`

日本語の「氏名」「お名前」、英語の `name`、`full name` のように姓と名を分離できない語は未対応とする。メール、住所、会社名、ユーザー名など別用途を示す語がある欄も除外する。

### 優先順位と安全策

1. 「英字」「ローマ字」など文字種が明示された日本語表現を最優先する。
2. 明確な日本語の「姓」「名」を日本語項目へ割り当てる。
3. 英語表現と `autocomplete="family-name"` / `given-name` を英字項目へ割り当てる。
4. 複数項目が同点になる曖昧な欄、閾値未満の欄は入力しない。

利用者がボタンを押した時点の登録値で、対応すると判定されたすべての欄を更新する。ただし登録値が空文字列の項目は入力しない。既存の値がある対応欄も、明示操作であるため登録値に置き換える。未対応欄の値は変更しない。

## 値の設定

対象欄のネイティブな `value` セッターを使って値を設定し、その後にバブリングする `input` イベントと `change` イベントを順に送出する。これにより通常のHTMLフォームに加え、イベントを監視するフロントエンドにも変更を通知する。

クリック、フォーカス、Enterキー送信、`form.submit()`、送信ボタン操作は一切行わない。

## 処理フロー

### 保存

1. ポップアップ表示時に `profile-storage.js` が `chrome.storage.local` からプロフィールを取得する。
2. 欠落した項目を空文字列で補い、4入力欄へ表示する。
3. 利用者が「保存」を押すと、入力値を前後トリムして `profile` として保存する。
4. 成功または失敗をポップアップ内へ表示する。

### 自動入力

1. 利用者が「このページに入力」を押す。
2. `popup.js` が現在のアクティブタブを取得する。
3. `autofill.js` と `content.js` を同じ注入処理で現在のページへ順番に実行する。
4. `content.js` が保存済みプロフィールを取得し、対象入力欄を判定して値を設定する。
5. 入力件数をポップアップへ返し、成功、該当欄なし、登録値なし、または実行不可を表示する。

## エラー処理

- 保存・取得失敗: 個人情報をログ出力せず、ポップアップへ日本語の失敗メッセージを表示する。
- 登録値がすべて空: 注入せず、「先にプロフィールを保存してください」と表示する。
- 対応欄が0件: 「対応する入力欄が見つかりませんでした」と表示する。
- 注入禁止ページまたはタブ取得失敗: ページを変更せず、「このページでは入力できません」と表示する。
- 一部の要素で値設定に失敗: 他の要素の処理を継続し、成功件数と失敗件数を結果へ含める。

## セキュリティとプライバシー

- 外部通信を行わず、外部スクリプトやCDNを読み込まない。
- 個人情報をソース、テストデータ、ログ、エラーメッセージへ含めない。
- `storage`、`activeTab`、`scripting` 以外の権限を要求しない。
- 自動入力は利用者がボタンを押した現在のタブだけで実行する。
- Content Security Policyに適合するよう、インラインJavaScriptと動的コード評価を使わない。

## テスト方針

Node.js組み込みの `node:test` と `assert` を使い、外部依存なしで単体テストする。最初に失敗するテストを書き、その後に最小実装を追加する。

自動テストでは少なくとも以下を確認する。

- 4項目が保存時に正規化され、次回取得時に復元される。
- 未保存または一部欠落したデータが安全に空文字列へ補完される。
- `label`、`placeholder`、`name`、`id`、`aria-label`、`autocomplete` の代表例を4項目へ判定できる。
- 「氏名」「full name」「email」「address」「company」など未対応または別用途の欄を判定しない。
- 空の登録値を入力しない。
- 対応欄だけが変更され、`input` と `change` が送出される。
- どのコードパスからもフォーム送信処理を呼ばない。

ブラウザでの手動確認では `tests/fixtures/test-form.html` を開き、次を確認する。

1. `chrome://extensions` からデベロッパーモードでフォルダーを読み込める。
2. 4項目を保存後、ポップアップを閉じて開き直しても値が残る。
3. テストフォームの対応する4入力欄へ登録値が入る。
4. メール、住所、会社名、氏名の欄は変更されない。
5. 「このページに入力」ではフォームが送信されない。

## 完了条件

- `manifest.json` がManifest V3として妥当で、Chromeに展開済み拡張機能として読み込める。
- 保存、復元、自動入力、未対応欄の保護を自動テストと手動確認用フォームで検証できる。
- 実行時依存および開発依存が0件である。
- git commitおよびgit pushを実行しない。
